# 节点国旗处理

全局设置中的“国旗处理方式”提供三种模式。订阅组可单独设置，也可继承全局。

| 模式     | 名称处理                                                                                    |
| -------- | ------------------------------------------------------------------------------------------- |
| 自动补齐 | 识别国家/地区，补齐对应国旗。无法识别时使用 `🌍`。国家旗帜和 `🌍` 按所选前缀/后缀位置排列。 |
| 保留原名 | 不自动增删、调整旗帜。用户启用的前缀和重命名规则仍执行。                                    |
| 移除旗帜 | 仅移除国家/地区旗帜和 `🌍`，保留 `⚡`、`🚀`、`🏁`、彩虹旗及其他 Emoji。                     |

命名模板中的 `{emoji}` 决定位置，优先于前缀/后缀设置。自动模式下，模板没有 `{emoji}` 就不补旗。移除模式会清理模板产生的国家旗帜和 `🌍`；保留模式仍执行显式模板。

国家识别根据原始旗帜、国家/机场代码、名称别名和覆盖规则进行，不查询出口 IP。国家/地区代码独立于显示映射，例如 TW/CN 始终区分，显示沿用项目现有约定。机场名前缀不会覆盖原始节点的国别信息。

普通协议/服务标签（例如 SS、VMESS、WS、CF、AI）不会被当作国家代码。需要指定对应国家时，可使用完整国家名称、实际国旗或地区覆盖规则。

## 地区覆盖

每条覆盖规则可选择：

- **仅影响分组**：修正内置或本地模板的地区分组，不改旗帜及命名变量。
- **分组、旗帜和命名变量**：同时修正地区、自动旗帜及 `{region}`、`{regionZh}`、`{countryCode}` 的值。

匹配按规则顺序进行；国家旗帜和 `🌍` 不阻挡名称正则的匹配。设置页面可粘贴样本名称，实时查看命中数量、前后结果及识别依据。表格仅显示前 50 条，统计包括全部样本。第三方转换器的自有分组规则由其配置决定。

订阅组可以仅继承全局规则、优先匹配组内规则后继续匹配全局，或仅使用组内规则。追加模式下，组内规则先于全局规则；每个作用范围按顺序使用第一条命中的规则。修改组内规则会使该订阅组的聚合缓存失效，不修改其他组或全局规则。

样本预览与订阅输出共用筛选、正则重命名、多模板、受限 DSL 脚本、排序和去重处理链。表格显示输出序号、过滤结果和各步骤的规则命中统计，包含后来被过滤的节点。支持每行输入完整节点链接，以便正确预览协议和服务器变量；仅输入名称时使用 `unknown` 协议和样本地址。样本在本地 Worker 中处理，不下载订阅或上传节点链接。

处理链按节点记录保留身份和地区提示，链接被改名成相同文本时也不会混用来源、地区或输出序号。地区筛选同时支持中文名称和 ISO 代码。Worker 最多保留一个正在处理的任务和一个最新待处理任务；更新期间的旧结果不能用于指定落地地区，处理失败后会清理旧结果。

## 多地区识别

`香港→日本`、`HK -> JP`、`US 出口: Japan` 等明确落地标记优先选择落地地区，并展示各候选地区与依据。`US/JP`、多个不同国旗等未能确定落地地区的名称使用 `🌍`，保留其他 Emoji；保留原名模式仍保留输入名称。

预览中的“指定落地地区”会添加一条精确匹配名称、同时修正地区和旗帜的规则；订阅组预览优先写入组内规则。复合地名（例如 North Korea、Guinea-Bissau）不会因其子地名产生冲突。机场名前缀继续使用原始节点的国别提示。

## 缓存处理版本

`shared/node-processing-version.js` 集中定义处理版本；升级地区识别或处理链语义时递增。聚合缓存与单订阅保护性缓存均写入版本。版本缺失或不一致的缓存会重新生成，成功刷新后写回新版本，不参与旧缓存的缩水回退。后台刷新使用独立的地区提示，地区规则变化时也不会复用旧规则产生的单订阅缓存。

当前版本为 `node-flags-v5`，包含逐节点地区提示、预览来源身份、ISO 筛选、源模板缓存依赖修复，以及相同输出链接按位置保存的地区身份。此前的 `node-flags-v2` / `node-flags-v3` / `node-flags-v4` 缓存会重新生成。源级重命名使用 `{emoji}` 变量（含 `{emoji:UPPER}` 等修饰符）时，缓存还会校验生成该变量时的生效策略，避免切换模式后复用旧模式生成的名称。不依赖该变量的源缓存仍可跨国旗模式复用。旧版重命名脚本中的声明式模板继续通过受限 DSL 执行。

## URL 与兼容

- `?emoji-mode=auto|preserve|remove`
- `?emoji-position=prefix|suffix`
- 旧的 `?emoji=true|false` 和 `enableFlagEmoji`、`addFlagEmoji` 布尔设置仍受支持；false 对应移除模式。
- 新模式启用后，第三方转换请求会关闭其额外添旗，名称先在本地处理。

网页名称及地区图标使用本地 SVG，复制的节点链接、订阅名称仍按 Emoji 策略输出。SVG 来自 flag-icons 7.6.0，MIT 许可证和来源记录位于 `public/flags/`。

## 性能验证

运行 `npm run benchmark:node-flags` 可以复现名称处理微基准。以下是 2026-11-16、增加完整处理链和冲突诊断前的历史测量；固定样本包含已知和未知地区，重复三个处理阶段，报告三个测量轮次的中位数。

Windows / Node v24.9.0 的一次测量：

| 节点数 |   修改前 | 新实现不使用请求缓存 | 新实现使用请求缓存 |
| ------ | -------: | -------------------: | -----------------: |
| 1,000  |   335 ms |               660 ms |             154 ms |
| 10,000 | 3,619 ms |             6,433 ms |           2,033 ms |

完整国家代码表和诊断信息增加了冷处理成本，请求内复用避免重复匹配。名称和地区提示缓存均有 20,000 条容量上限，随请求释放，不在 Worker 全局保存节点名称。万级样本测量中的进程堆用量约 19.7 MB（包含样本数据），原实现约 10.4 MB。此测试测量名称/旗帜 CPU 处理，不包含订阅网络下载或客户端加载时间。

运行 `npm run benchmark:node-processing` 验证 1,000 / 10,000 个混合协议节点。Trojan、VMess、SSR、SS、VLESS、Hysteria2、TUIC、AnyTLS 各占八分之一；包含未知地区、多地区冲突、明确落地和旗帜身份样本。脚本执行解析、完整订阅转换和本地预览计算，并断言节点数量和每个输出名称完全一致，记录三个测量轮次的中位数及内存。

针对重复地区识别，内部读取名称和连接信息时跳过无用的识别，并在同一请求中共享原始地区及两种规则作用范围的缓存。订阅组预览的来源查找改为一次构建索引，避免逐节点重新解析、扫描全部来源。

2026-11-17，Windows / Node v24.9.0 的混合协议测量：

| 节点数 |     解析 | 订阅转换 | 预览计算 | 三阶段合计 |
| ------ | -------: | -------: | -------: | ---------: |
| 1,000  |   209 ms |   502 ms |   492 ms |   1,203 ms |
| 10,000 | 2,087 ms | 4,729 ms | 4,603 ms |  11,357 ms |

优化前万级三阶段合计约 19,582 ms，预览计算约 10,029 ms；分别减少约 42% 和 54%。来源查找的千级旧路径约 700–1,133 ms，索引方式约 3 ms，万级索引约 20 ms。原始测量文件位于 `tmp/node-processing-mixed-benchmark-before.json` 和 `tmp/node-processing-mixed-benchmark-after.json`。

混合基准的合计时间包括订阅转换和预览这两次独立处理；不包含网络下载或 DOM 绘制。堆分配增量和强制回收后的保留增量分开记录，进程 RSS 包含模块与 V8 保留内存，不应当作为单次请求的堆用量。浏览器测试另行验证 Worker、桌面和手机布局、冲突选择、完整处理链及 SVG 加载。
