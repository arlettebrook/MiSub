## 已复现并修复的问题

| 问题                       | 触发条件与影响                                                                                                  | 修复                                                         |
| -------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 旧版重命名模板不执行       | `nodeTransform.rename.script` 使用声明式模板；共享适配器转成被禁用的 `code` 算子后，原本工作的预览重命名失效    | 继续通过受限 DSL 处理模板，不启用任意 JavaScript             |
| 模板修饰符漏判             | 使用 `{emoji:UPPER}{name}` 等有效模板时，策略误认为没有国旗变量，移除了国旗                                     | 模板策略、名称净化与源缓存依赖共用变量识别                   |
| 相同输出链接混用地区       | 两条名称为不同国旗加 `Premium` 的节点，去旗帜或重命名后链接相同；订阅配置与缓存回放把两条节点都归入最后一个地区 | 请求内按输出位置保存地区提示，转换与缓存序列化按位置读取     |
| 订阅组设置显示与实际不一致 | 原有设置在 `nodeTransform` 或所选预设内；界面误显示为继承全局                                                   | 正确读取组内配置和预设，打开界面不修改草稿                   |
| Sing-box 地区分组丢失      | “仅影响分组”的规则命中过原始名称，随后名称改成通用名称；出站转换丢掉地区元数据                                  | 策略组使用保留地区元数据的内部记录，最终 JSON 不输出内部字段 |
| 异常历史预设导致抛错       | `nodeTransformPresets` 为非数组，或数组含 `null`；国旗策略抛错，影响订阅生成                                    | 忽略异常容器和空条目，沿用正常的全局回退                     |

处理版本更新为 `node-flags-v5`，避免继续读取旧处理结果。保护性缓存浏览器测试的样本同时补齐处理版本，继续验证兼容缓存回退，而不是使用应当失效的旧版本样本。
